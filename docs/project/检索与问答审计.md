## 发现并修复的问题

1. 长篇文档中零散出现几个短词就可能排在前面。现在以完整题名和局部正文为主要证据；相近写法使用字符片段覆盖率，结果按相关度降序排列。纯数字编号只接受精确匹配，避免把“3830”模糊匹配成“3820”。
2. OCR 文字有空格和标点时，结果摘要可能偏离真实命中位置。现在把规范化命中映射回可见原文，从相同位置生成摘要和高亮，并保留所在原始页码。
3. “港口与对外开放”等组合关键词分布在不同段落时会漏检。现在允许多个关键词在同一文档内分别命中；这种结果的排名低于同一局部段落中的完整命中。
4. “GDP 目标→GNP 目标→这些目标都实现了吗”丢失较早的 GDP 问题。现在同一会话保留最近四轮独立问句；1995 年 GNP 的评估采用原始目标表所列 221 亿元，并与 GDP 的 204.8 亿元目标分开计算和标注来源。
5. “这个数字为什么有不同版本”被误读为“3820”的三个数字；“目标实现了吗”没有继承上一问的 2000 年目标。现在分别继承指标、年份和目标语境。
6. 老市区布局问题曾误入空间工具；生态建设问题曾被改写成宽泛布局；未收录的 1997 年 GDP 曾被替换为所有已收录年份。现在分别路由到规划资料、环境资料和明确的缺数状态。
7. 对未收录年份，豆包有一次声称外部权威数据未披露。服务现在拒绝这类无依据的外部资料缺失断言；没有可靠数值时保留简短回答，并在页面下方说明本地指标表的覆盖情况。

## 仍有的资料边界

未收录年份的准确指标数值、缺少统一比较口径的定性目标，不能仅靠问题改写或模糊检索得出。系统会保留依据不足状态，不把邻近年份、不同统计版本或模型猜测当作确定事实。完整资料文件不随 Git 提交；服务器运行上述检索仍需同步 `knowledge/library/` 的文件本体。
